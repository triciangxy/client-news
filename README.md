# Client Pulse

Dashboard for tracking news and price moves across our key APAC clients.

Two tools live in this repo, sharing the same build pattern (a scheduled GitHub
Action writes a JSON file; a static page reads it):

- **Client Pulse** — `/` — news and price moves across existing key clients.
- **[Taiwan Prospect Radar](prospects/)** — `/prospects/` — TWSE-listed issuers,
  the individuals and families that control them, and an estimate of what they
  are worth. See [Taiwan Prospect Radar](#taiwan-prospect-radar) below.

## What's in this repo

| File | What it does |
|---|---|
| `index.html` | The Client Pulse dashboard. Reads `data.json` and renders. |
| `data.json` | Cached headlines + quotes. Regenerated by the workflow. |
| `fetch_news.py` | Python script that pulls news + quotes. Runs on GitHub Actions. |
| `.github/workflows/refresh.yml` | Scheduled job that runs `fetch_news.py` and commits the result. |
| `prospects/index.html` | The Taiwan Prospect Radar dashboard. |
| `prospects/roster.json` | Curated: who controls which TWSE issuer, and roughly what share. |
| `prospects/data.json` | Computed output. Regenerated by the workflow. |
| `fetch_twse.py` | Pulls TWSE open data and builds `prospects/data.json`. |
| `.github/workflows/refresh-prospects.yml` | Scheduled job for the Taiwan tool. |

## How it works

1. Every 30 minutes (during APAC business hours, Mon–Fri), GitHub Actions runs `fetch_news.py` on a free Ubuntu runner.
2. The script fetches stock quotes (Yahoo Finance chart endpoint) and headlines (Google News RSS filtered to each client's domain).
3. It writes results to `data.json` and commits it back to the repo.
4. GitHub Pages serves `index.html`, which reads the latest `data.json` and renders the cards.

No CORS proxies. No paid APIs. No server infrastructure to maintain.

## First-time deployment (one-time setup, ~10 min)

### Step 1 — Create the repo

1. On GitHub, click **New repository**.
2. Name it something unguessable, e.g. `cp-internal-x7k2`. **Public** (Pages on private repos requires a paid plan).
3. Don't add a README or .gitignore — we'll push the files directly.

### Step 2 — Push these files

Drag and drop all four files into the repo on github.com (use **Add file → Upload files**):
- `index.html`
- `data.json` (the starter file with the most recent run included)
- `fetch_news.py`
- `.github/workflows/refresh.yml` (you'll need to type the path manually since GitHub's drag-and-drop doesn't preserve folders — easier: create the file via **Add file → Create new file**, name it `.github/workflows/refresh.yml`, paste the contents)

Commit to the `main` branch.

### Step 3 — Enable GitHub Pages

1. Repo → **Settings** → **Pages** (left sidebar).
2. **Source**: Deploy from a branch.
3. **Branch**: `main`, folder `/ (root)`. Save.
4. After ~30 seconds, the URL appears at the top of the Pages settings: `https://<your-username>.github.io/cp-internal-x7k2/`.

### Step 4 — Grant the workflow permission to push

1. Repo → **Settings** → **Actions** → **General** (left sidebar).
2. Scroll to **Workflow permissions**.
3. Select **Read and write permissions**. Save.

This lets the scheduled job commit updates to `data.json`.

### Step 5 — Trigger the first run manually

1. Repo → **Actions** tab.
2. Click **Refresh Client Pulse Data** on the left.
3. Click **Run workflow** → **Run workflow**.
4. Wait ~30 seconds. It should commit a fresh `data.json`.

Open your Pages URL — you should see the dashboard with live data.

## Editing the client list

Edit the `CLIENTS` list at the top of `fetch_news.py`. Each entry can have:

| Field | Required | Notes |
|---|---|---|
| `name` | yes | Display name shown on the card |
| `short` | yes | Short key used internally |
| `type` | yes | One of: `listed`, `sovereign`, `pension`, `insurance`, `bank` |
| `country` | yes | Display label |
| `ticker` | listed only | Yahoo Finance ticker (e.g. `1299.HK`, `7182.T`, `055550.KS`) |
| `aum` | private only | AUM in USD billions, for display |
| `earnings` | optional | ISO date `YYYY-MM-DD` of next confirmed earnings |
| `blurb` | optional | One-line description shown in the detail drawer |
| `newsroom` | optional | URL to the client's press page |
| `sources` | yes | List of news sources, tried in priority order |

Each source has `type` (badge category), `label` (what shows on the card), `kind` (`google-news` or `rss`), and either `query` (for google-news) or `url` (for rss).

After editing, commit the change. The next scheduled run will pick it up, or trigger it manually from the Actions tab.

## Schedule

The default cron `*/30 0-10 * * 1-5` runs every 30 min from 00:00–10:00 UTC, Monday–Friday (Singapore: 08:00–18:00 SGT). Edit `.github/workflows/refresh.yml` to change it.

GitHub Actions sometimes delays scheduled jobs by a few minutes when their runners are busy — that's normal, not a bug.

## Sharing with colleagues

Just send them the Pages URL. They don't need a GitHub account or any permissions; the page is static HTML.

## Updating the dashboard look

Edit `index.html` and commit. GitHub Pages will redeploy in ~30 seconds.

## Troubleshooting

**"Could not load data.json" error on the page**
→ The workflow hasn't run yet, or it failed. Check the Actions tab.

**Workflow fails with permission error**
→ You skipped Step 4 above. Go back and grant write permissions.

**Cards show "no source"**
→ The fetcher couldn't reach Google News for that client. Could be transient — try re-running. If persistent, the `site:` filter for that domain may need to be broadened.

**Yahoo quote endpoint stops working**
→ Yahoo occasionally changes endpoints. If quotes go missing, the chart endpoint in `fetch_quote_chart()` is the most-stable replacement; for production-grade reliability, swap to a paid feed (Polygon, IEX Cloud, FMP).

# Taiwan Prospect Radar

**Audience:** Taiwan private bankers.
**Job:** identify prospects among the controlling shareholders of TWSE-listed
companies, with an estimate of net worth and of how much cash is actually
bankable this year.

Live at `/prospects/` once Pages is enabled.

## How the estimate is built

The tool separates what moves daily from what does not.

| Layer | Source | Refresh |
|---|---|---|
| Who controls which issuer, and roughly what share | `prospects/roster.json` — desk-curated | manual, when filings change |
| Price, shares outstanding, dividend yield, P/E, monthly revenue | TWSE open data | twice each trading day |
| Insider share counts and pledge ratios | MOPS (best effort) | each run, where the scrape succeeds |
| USD/TWD | Yahoo chart endpoint | each run |

The maths, in full:

```
stake value    = Σ ( shares outstanding × stake % × last close )
net worth mid  = stake value × unlisted uplift        (1.25×–1.85× by archetype)
range          = mid ± 25%
bankable cash  = Σ ( shares held × trailing DPS ) × (1 − 28% dividend tax) × 60%
```

Listed stake value is the only directly observable term. The uplift stands in
for property, unlisted operating companies, cash and offshore assets — it is the
crudest assumption in the model, and every parameter sits in the `assumptions`
block of `roster.json` so it can be argued with and changed.

**Prospect score (0–100)** weights estimated wealth (40, log-scaled), bankable
cash (30, log-scaled), live catalysts (20) and accessibility (10). Accessibility
is marked *down* when the subject's own family runs a competing onshore private
bank, and *up* for low-profile, under-covered or already-offshore subjects.

## Why these signals

Three things about Taiwan drive the design:

- **Dividends are seasonal.** Almost all cash dividends go ex between June and
  September. The dividend run-rate is therefore a dated, plannable liquidity
  event, not an abstraction — it is the single most actionable number here.
- **Monthly revenue is published on the 10th.** No other major market gives you
  a fundamental datapoint that fresh; it feeds the momentum signal.
- **Share pledging is disclosed.** A high pledge ratio means a lending
  relationship already exists somewhere else — that is competitive intelligence,
  and refinancing is the wedge.

## Coverage and its limits

- TWSE (上市) only. TPEx/OTC (上櫃) issuers are not covered — adding them means
  pointing the fetcher at the TPEx open-data host as a second source.
- Stake percentages are **desk estimates** unless a row is marked
  *filings-verified*, which happens only when the MOPS scrape succeeds for that
  issuer. Every row links to the underlying MOPS page. **Verify before any
  client contact.**
- Family-level rows (e.g. 王氏家族) cannot be split between members.
- Blocks held through foundations and public-interest trusts — Formosa Plastics
  being the clearest case — are deliberately under-attributed. Do not read a
  group's market cap as family wealth.
- Unlisted companies, real estate and offshore assets are never observed
  directly; they only enter through the uplift factor.

## Extending coverage

Edit `prospects/roster.json`. Add a company object with a `principals` list:

| Field | Notes |
|---|---|
| `subject_id` | slug; **reused across companies** to aggregate one person's multiple holdings |
| `name_zh` / `name_en` | Chinese name is what the MOPS scrape matches on |
| `subject_type` | `individual` or `family` |
| `archetype` | picks the uplift: `founder_operator`, `family_office`, `financial_group`, `professional_exec`, `property_developer` |
| `stake_pct_est` | best estimate; overridden automatically when MOPS returns a filed number |
| `stake_basis` | what the percentage actually covers — shown under the holding |
| `confidence` | `high` / `medium` / `low`, surfaced in the UI |
| `base` | primary city; drives the territory filter |
| `vehicles` | known holding companies and foundations; searchable |
| `tags` | drive signals and the accessibility score (see `fetch_twse.py`) |

Commit, then trigger **Refresh Taiwan Prospect Radar** from the Actions tab.

## Working on it locally

```sh
python fetch_twse.py --synthetic --out /tmp/preview/data.json  # no network, fake prices
python fetch_twse.py --skip-mops                               # live, skips the slow scrape
```

`--synthetic` generates a deterministic fake market so the page can be styled
without network access. Never commit its output.

## Not for client distribution

Both dashboards are for internal use. They aggregate publicly-available
information; not investment advice. The Taiwan tool in particular produces
**modelled estimates about identifiable private individuals** — treat the output
as a research lead list, handle it under the same confidentiality rules as any
prospect file, and do not present its figures to a client as fact.
